# Document Extension Development Guide

Blueprint for adding a Quarkus JNoSQL extension for a **document** database. Reference implementation: **MongoDB**
(`mongodb/`). Read [`common.md`](common.md) first for the generic module layout, build items, CDI/Arc, native image,
testing commands and the generic Definition of Done. This guide only covers what is specific to the document model.

MongoDB is an architectural example, not a template to copy blindly; section 6 separates reusable decisions from
MongoDB-specific ones.

## 1. Purpose

A document extension lets an application inject, for a document database:

- `jakarta.nosql.Template` qualified with `@Database(DatabaseType.DOCUMENT)`,
- Jakarta Data repositories (`@Repository` interfaces extending `org.eclipse.jnosql.mapping.NoSQLRepository`),
- the communication-layer manager (here `MongoDBDocumentManager`).

The extension provides Quarkus wiring only: how the driver's manager factory is obtained (from Quarkus-managed
configuration or client), CDI producers, exclusions of Eclipse suppliers, extension metadata, codestart and tests.

## 2. Architecture

| Layer | Owner | MongoDB example |
|---|---|---|
| Wire protocol and client | Driver and, here, Quarkus | `com.mongodb.client.MongoClient` from `io.quarkus:quarkus-mongodb-client` |
| Document communication contracts | Eclipse JNoSQL (`org.eclipse.jnosql.communication.semistructured`) | `DatabaseConfiguration`, `DatabaseManagerFactory` |
| Driver implementation | `org.eclipse.jnosql.databases:jnosql-mongodb` | `MongoDBDocumentManager`, `MongoDBDocumentManagerFactory` |
| Entity mapping, `Template`, repositories, query translation | Eclipse JNoSQL mapping (`jnosql-mapping-semistructured`, pulled by `quarkus-jnosql-core`); entity metadata generated by `mapping-lite-processor` | `@Entity`, `@Id`, `@Column` on `Person` |
| Quarkus wiring | **This extension** | `mongodb/runtime`, `mongodb/deployment` |

Entity mapping is not implemented in the extension. Metadata is generated at compile time by the JNoSQL Lite processor
(declared in `mongodb/runtime/pom.xml`; the application's compiler must run it, see the README section
"Enabling the JNoSQL Mapping Lite Annotation Processor"). `core` registers the mapping SPI and the reflective hierarchy of `@Entity`/`@Embeddable` classes
(`core/deployment/.../Processor.java`), so a document extension does not repeat it.

Runtime flow:

1. The application sets `jnosql.document.database` (`MappingConfigurations.DOCUMENT_DATABASE`).
2. `QuarkusMongoDBDatabaseManagerProducer` (extends `AbstractDatabaseManagerProducer`) obtains the factory from
   `QuarkusMongoDBDocumentConfiguration`, reads the database name through `MicroProfileSettings`, and produces a
   `MongoDBDocumentManager` qualified `@Database(DatabaseType.DOCUMENT)` and `@Default`.
3. Eclipse JNoSQL's template and repository beans resolve that manager.

### 3.3 CDI registration and build items

`Processor` (feature `jnosql-mongodb`) produces:

- `AdditionalBeanBuildItem.unremovableOf` for `QuarkusMongoDBDocumentConfiguration` and `QuarkusMongoDBDatabaseManagerProducer`.
- `ExcludedTypeBuildItem` for `org.eclipse.jnosql.mapping.document.configuration.DocumentManagerSupplier` and
  `org.eclipse.jnosql.databases.mongodb.mapping.DocumentManagerSupplier`.

There are no native-image build items in the MongoDB `Processor`; native behavior of the client comes from
`quarkus-mongodb-client`, and entities/SPI from `core`.

### 3.4 Configuration

[`application.properties`](../mongodb/integration-tests/src/main/resources/application.properties) of the integration app:

```properties
jnosql.document.database=test
```

There is no connection property in the app: Quarkus Dev Services for the MongoDB client start a database during tests,
and connection settings belong to `quarkus-mongodb-client`. `quarkus-extension.yaml` lists the prefixes `jnosql.` and
`jnosql.document.`.

## 4. Implementation workflow

Steps match section 3 of [`common.md`](common.md). **R** = required, **O** = optional/conditional.

1. **Prerequisites (R).** Confirm `jnosql-<db>` for the managed `jnosql.version`; identify its
   `DatabaseConfiguration`, manager/factory classes, `*Configurations` enum and CDI suppliers
   (`DocumentManagerSupplier` variants). Check for a Quarkus client extension.
2. **Maven modules (R).** `<db>/pom.xml`, `runtime`, `deployment`, `integration-tests`; register in the root `pom.xml`.
3. **Dependencies (R).** As 3.1. Exclude the unused model mapping (`jnosql-mapping-key-value`) and `jnosql-mapping-reflection`.
   (O) the Quarkus client extension and its `-deployment` artifact when it exists.
4. **Runtime integration (R).**
   - `@Singleton` `Quarkus<Db>DocumentConfiguration implements DatabaseConfiguration`, returning the driver's
     `DatabaseManagerFactory`. If a Quarkus-managed client exists, `@Inject` it and hand it to the factory (MongoDB). If the
     driver creates the client from `Settings`, delegate to the driver configuration and own the factory lifecycle
     (compare `cassandra/` and the caching in the Redis guide, [`key-value.md`](key-value.md)).
   - `@Singleton` producer extending `AbstractDatabaseManagerProducer<Manager, Factory, Configuration>` with
     `@Produces @Priority(1) @Alternative @Default @Database(DatabaseType.DOCUMENT)` and `get(MappingConfigurations.DOCUMENT_DATABASE)`.
5. **Deployment integration (R).** `Processor` with `FeatureBuildItem`, unremovable beans, excluded suppliers.
6. **CDI registration (R).** As 3.3; verify excluded class names in the driver jar.
7. **Configuration (R).** `jnosql.document.database` plus the properties of the client extension or driver. No new properties.
8. **Native image (O).** Add only after a native failure or a known driver need; MongoDB needed none.
9. **Integration tests (R).** Section 7.
10. **Build validation (R).** Section 7 and the checklist in section 8.
11. **Codestart (O, expected for document).** Descriptor under `<db>/runtime/src/main/codestarts/quarkus/quarkus-jnosql-<db>-codestart/`,
    set `data.database-type: "document"` and `database-name`, and copy `codestarts/semistructured` through the runtime
    pom as MongoDB does.

## 5. Reference code

Configuration (`QuarkusMongoDBDocumentConfiguration`):

```java
@Singleton
public class QuarkusMongoDBDocumentConfiguration implements DatabaseConfiguration {

    @Inject
    protected MongoClient client;

    @Override
    public MongoDBDocumentManagerFactory apply(Settings settings) {
        return new MongoDBDocumentManagerFactory(this.client);
    }
}
```

Producer (`QuarkusMongoDBDatabaseManagerProducer`):

```java
@Singleton
public class QuarkusMongoDBDatabaseManagerProducer extends
        AbstractDatabaseManagerProducer<MongoDBDocumentManager, MongoDBDocumentManagerFactory, QuarkusMongoDBDocumentConfiguration> {

    @Produces
    @Priority(1)
    @Alternative
    @Default
    @Database(DatabaseType.DOCUMENT)
    public MongoDBDocumentManager get() {
        return get(MappingConfigurations.DOCUMENT_DATABASE);
    }
}
```

Deployment (`Processor`):

```java
@BuildStep
void build(BuildProducer<AdditionalBeanBuildItem> additionalBeanProducer) {
    additionalBeanProducer.produce(AdditionalBeanBuildItem.unremovableOf(QuarkusMongoDBDocumentConfiguration.class));
    additionalBeanProducer.produce(AdditionalBeanBuildItem.unremovableOf(QuarkusMongoDBDatabaseManagerProducer.class));
}

@BuildStep
void buildExcludedType(BuildProducer<ExcludedTypeBuildItem> excludedTypeProducer) {
    excludedTypeProducer.produce(
            new ExcludedTypeBuildItem("org.eclipse.jnosql.mapping.document.configuration.DocumentManagerSupplier"));
    excludedTypeProducer.produce(
            new ExcludedTypeBuildItem("org.eclipse.jnosql.databases.mongodb.mapping.DocumentManagerSupplier"));
}
```

Application side, as exercised by `JNoSQLResource` (template and repository injection):

```java
@Inject
@Database(DatabaseType.DOCUMENT)
protected People people;          // @Repository interface People extends NoSQLRepository<Person, String>

@Inject
@Database(DatabaseType.DOCUMENT)
protected Template template;
```

Query integration in the shared codestart ([`Garage`](../codestarts/semistructured/java/src/main/java/org/acme/Garage.java),
tested through `CodestartTest`): Jakarta Data annotations `@Save`, `@Delete` and
`@Find` with `@By("transmission")`, `PageRequest` and `Sort`, on a `NoSQLRepository<Car, String>`. This exercise happens in
the generated project; the hand-written `People` repository in the integration app only uses inherited operations.

## 6. Design decisions and trade-offs

| Decision | Why | Reusable? |
|---|---|---|
| Inject Quarkus' `MongoClient` instead of building one from `Settings` | Connection configuration, Dev Services and native support stay in `quarkus-mongodb-client`; avoids a second connection config | Yes, whenever a Quarkus client extension exists. Otherwise build from `Settings` |
| `@Singleton` configuration that creates a new factory per `apply` | The factory only wraps the shared `MongoClient`, which Quarkus closes | MongoDB-specific. If the factory owns connections, cache and close it (see [`key-value.md`](key-value.md)) |
| Producer qualified `@Database(DatabaseType.DOCUMENT)` plus `@Default` | Matches the injection points of Eclipse JNoSQL and of applications, as in `JNoSQLResource` | Yes |
| Excluding two `DocumentManagerSupplier` classes | The mapping module and the driver each ship a supplier that would compete | Pattern yes; names are driver-specific |
| No native build steps | Nothing beyond `core` and the Quarkus client is needed | MongoDB-specific |
| Shared codestart `codestarts/semistructured` | Document and column extensions share the `NoSQLRepository` sample | Yes, for the same model family |

## 7. Testing

Follow `mongodb/integration-tests` and the generic guidance in [`common.md`](common.md#5-testing):

- **App module**: entities `Person` and `PersonRecord`, repositories `People` and `PeopleRecord`, REST `JNoSQLResource`,
  `META-INF/beans.xml` (`bean-discovery-mode="annotated"`), `application.properties`.
- **`JNoSQLResourceTest`** (`@QuarkusTest`, `@TestHTTPEndpoint`): parameterized over `/using-jakarta-nosql`,
  `/using-jakarta-nosql-record`, `/using-jakarta-data`, `/using-jakarta-data-record`. `JNoSQLResourceIT` extends it with `@QuarkusIntegrationTest`.
- **Database**: Dev Services (no test resource class). Use a `QuarkusTestResourceLifecycleManager` with Testcontainers when the
  Quarkus client has no Dev Services (see `QdrantTestResource` or `RedisTestResource`).
- **`CodestartTest`**: `checkGeneratedSource("org.acme.Car")`, `checkGeneratedSource("org.acme.Garage")`,
  `checkGeneratedTestSource("org.acme.GarageTest")` and `buildAllProjects()` against snapshots.
- Note: the MongoDB integration app does not contain derived or annotated query tests of its own; add tests for the
  query features you claim, since query support depends on the driver and database.

```bash
mvn -pl mongodb -am clean install                       # replace mongodb with <db>
mvn -pl mongodb/integration-tests verify -DskipITs=false
mvn -B clean install -Dno-format                        # whole reactor, as CI
```

Docker is required for Dev Services and Testcontainers.

## 8. Definition of Done

Complete the [common checklist](common.md#7-definition-of-done) plus:

- [ ] Configuration implements `DatabaseConfiguration`; client ownership decided (Quarkus client or driver-created) and its lifecycle handled.
- [ ] Producer extends `AbstractDatabaseManagerProducer`, qualified `@Database(DatabaseType.DOCUMENT)`, `@Default`, `@Alternative`, `@Priority(1)`.
- [ ] Eclipse `DocumentManagerSupplier` classes (mapping and driver) excluded; names verified.
- [ ] `jnosql-mapping-reflection` and unused mapping modules excluded; `mapping-lite-processor` declared.
- [ ] Integration app proves `Template` and repository paths for a class and a record entity.
- [ ] Tests for every query feature claimed (derived/`@Find`/Jakarta Query, pagination, sorting) run against the real database.
- [ ] Codestart (`database-type: "document"`) and `CodestartTest` snapshots present and updated.
- [ ] Native build run or limitation noted.
- [ ] Conventional Commits, one logical change per commit.
